# Вимоги до клієнтського застосунку «Psycho Program»

Документ описує вимоги до мобільного застосунку для **клієнтів (пацієнтів)** —
частини платформи Psycho Program. Через застосунок клієнт отримує від психолога
активності та програми, виконує їх і веде щоденник самопочуття (зокрема голосом).

- **Версія документа:** 1.0
- **Дата:** 16.06.2026
- **Статус:** реалізований прототип (MVP)
- **Платформа:** Android та iOS (нативний застосунок на Expo / React Native)

---

## 1. Призначення та контекст

### 1.1 Мета
Дати клієнту психолога зручний мобільний інструмент, щоб:
- бачити призначені психологом вправи (активності) та програми;
- виконувати їх і надсилати відповіді психологу;
- щодня вести щоденник настрою — текстом або голосом;
- мати доступ до матеріалів, якими ділиться психолог.

### 1.2 Місце в системі
Застосунок — один із трьох компонентів платформи:
1. **Адмін-панель психолога** (веб) — психолог створює контент і веде клієнтів.
2. **Бекенд** (REST API, Node + PostgreSQL) — спільне джерело даних і авторизація.
3. **Клієнтський застосунок** (цей документ) — мобільний застосунок пацієнта.

Застосунок не має власної бази даних: усі дані надходять і зберігаються через
бекенд (`/api/client/*`, `/api/journal`, `/api/auth/*`).

### 1.3 Користувачі
- **Клієнт (пацієнт)** — єдина роль застосунку. Доступ — лише до власних даних.
- Психолог застосунком **не** користується (працює у веб-адмінці).

---

## 2. Межі (Scope)

### 2.1 Входить у MVP
- Вхід та активація акаунта за запрошенням.
- Перегляд призначених активностей і програм.
- Виконання активності (відповіді) і її завершення.
- Щоденник: текстові та **голосові** записи з настроєм; перегляд відповідей психолога.
- Матеріали (файли/посилання від психолога).
- Профіль і вихід.

### 2.2 Не входить у MVP (можливі наступні ітерації)
- Пуш-сповіщення про нові завдання.
- Чат із психологом у реальному часі.
- Самостійна реєстрація без запрошення.
- Офлайн-режим із синхронізацією.
- Редагування/видалення вже надісланих записів щоденника.
- Нагадування та розклад у застосунку.

## 3. Ролі та доступ

| Вимога | Опис |
|---|---|
| AC-1 | Застосунок доступний лише користувачам із роллю `CLIENT`. Спроба входу акаунтом психолога відхиляється з поясненням. |
| AC-2 | Клієнт бачить виключно власні дані (призначення, записи, матеріали), скоуповані за його профілем на бекенді. |
| AC-3 | Усі запити до API авторизуються JWT-токеном; без валідного токена доступ заборонено. |

## 4. Функціональні вимоги

### 4.1 Автентифікація та активація за запрошенням
| ID | Вимога |
|---|---|
| FR-1.1 | Психолог запрошує клієнта в адмінці (за email). Клієнт **активує** акаунт у застосунку: вводить цей email і задає пароль (`POST /api/auth/client/claim`). |
| FR-1.2 | Клієнт із уже активованим акаунтом входить за email і паролем (`POST /api/auth/login`). |
| FR-1.3 | Сесія зберігається на пристрої (JWT у захищеному сховищі), щоб не входити щоразу. |
| FR-1.4 | Помилки входу/активації показуються зрозумілим текстом (невірні дані, email не запрошено тощо). |
| FR-1.5 | Користувач може вийти з акаунта (очищення токена). |

### 4.2 Головний екран — призначення
| ID | Вимога |
|---|---|
| FR-2.1 | Показ усіх призначень клієнта (`GET /api/client/deliveries`), розділених на **Програми** та **Активності**. |
| FR-2.2 | Кожне призначення має статус: **Нове** (`sent`), **В процесі** (`inProgress`), **Завершено** (`completed`). |
| FR-2.3 | Картка активності показує назву, опис, кількість елементів. Картка програми — назву, опис, кількість кроків. |
| FR-2.4 | Список оновлюється «потягни-щоб-оновити» та при поверненні на екран. |
| FR-2.5 | Персональне привітання з імʼям клієнта та згадкою його психолога. |

### 4.3 Програми
| ID | Вимога |
|---|---|
| FR-3.1 | Перегляд програми як послідовності кроків (активностей) із правилом доставки кожного: одразу / через N днів після попередньої / через N днів від старту. |
| FR-3.2 | Кроки відображаються візуально як маршрут (timeline) з назвами активностей. |
| FR-3.3 | Пояснення, що активності програми надходитимуть за розкладом і зʼявлятимуться на головному екрані. |

### 4.4 Активності
| ID | Вимога |
|---|---|
| FR-4.1 | Перегляд активності з усіма елементами (`GET /api/client/activities/:id`) лише якщо вона призначена клієнту (напряму або в межах програми). |
| FR-4.2 | Підтримка типів елементів: секція, інформаційний текст, відео/зображення (плейсхолдер), коротка відповідь, розгорнута відповідь, вибір варіанту, шкала 1–10. |
| FR-4.3 | Клієнт заповнює поля-питання та надсилає відповіді (`POST /api/client/deliveries/:id/complete`); статус стає **Завершено**. |
| FR-4.4 | Завершена активність відкривається лише для перегляду відповідей (без повторного редагування у MVP). |

### 4.5 Щоденник
| ID | Вимога |
|---|---|
| FR-5.1 | Перегляд власних записів щоденника у зворотному хронологічному порядку (`GET /api/journal`). |
| FR-5.2 | Створення нового запису: обовʼязковий **настрій** (5 рівнів: чудово / добре / нейтрально / погано / дуже погано), необовʼязкові заголовок і текст. |
| FR-5.3 | **Голосовий запис:** клієнт може записати голосову нотатку (мікрофон), бачити таймер запису, перезаписати або видалити перед збереженням. |
| FR-5.4 | Запис можна зберегти лише з голосом (без тексту), лише з текстом, або з обома. |
| FR-5.5 | Голосова нотатка надсилається на бекенд і прикріплюється до запису (`POST /api/journal` з аудіо у base64). |
| FR-5.6 | У записі з аудіо доступне **відтворення** нотатки (плеєр) і показ **транскрипції** (якщо вона виконана). |
| FR-5.7 | Якщо психолог відповів на запис — відповідь показується клієнту. |
| FR-5.8 | Статус транскрипції відображається («Розшифровуємо…», готовий текст або відсутність). |

### 4.6 Матеріали
| ID | Вимога |
|---|---|
| FR-6.1 | Перегляд файлів і посилань, якими психолог поділився з клієнтом (`GET /api/client/resources`). |
| FR-6.2 | Натискання на посилання відкриває його у браузері; для файлів показано тип і розмір. |

### 4.7 Профіль
| ID | Вимога |
|---|---|
| FR-7.1 | Показ імені, email клієнта та імені його психолога. |
| FR-7.2 | Кнопка виходу з акаунта. |

## 6. Технічні вимоги

### 6.1 Стек
- **Expo SDK 56 / React Native**, TypeScript.
- **React Navigation**: нижні таби (Головна, Щоденник, Матеріали, Профіль) + native stack для деталей (Активність, Програма).
- **AsyncStorage** — зберігання JWT-токена.
- **expo-audio** — запис і відтворення голосових нотаток (формат `.m4a`).
- **expo-file-system** — читання запису у base64 для відправки.

### 6.2 Інтеграція з API (використовувані ендпоінти)
| Метод | Шлях | Призначення |
|---|---|---|
| POST | `/api/auth/login` | Вхід клієнта |
| POST | `/api/auth/client/claim` | Активація акаунта за запрошенням |
| GET | `/api/client/me` | Профіль клієнта + психолог |
| GET | `/api/client/deliveries` | Призначені активності та програми |
| GET | `/api/client/activities/:id` | Деталі активності |
| POST | `/api/client/deliveries/:id/complete` | Завершення активності з відповідями |
| GET | `/api/client/resources` | Спільні матеріали |
| GET | `/api/journal` | Власні записи щоденника |
| POST | `/api/journal` | Створення запису (з опційним аудіо) |
| GET | `/api/journal/:id/audio` | Відтворення голосової нотатки |

### 6.3 Голосовий щоденник і транскрипція
- Голос записується на пристрої, надсилається у base64, зберігається на бекенді.
- **Транскрипція** виконується на бекенді через OpenAI Whisper у фоні, **якщо**
  заданий ключ `OPENAI_API_KEY`. Без ключа запис лишається лише як аудіо.
- Транскрипцію бачать і клієнт, і психолог; психолог може її відкоригувати.

### 6.4 Дозволи
- **Мікрофон** — для голосових нотаток (через плагін `expo-audio` з текстом-поясненням).

## 8. Критерії приймання (MVP)
Застосунок вважається готовим до демо, якщо клієнт може:
1. Активувати акаунт за запрошенням і увійти.
2. Побачити призначені програми й активності зі статусами.
3. Відкрити активність, заповнити відповіді й завершити її.
4. Створити запис у щоденнику текстом і **голосом**, відтворити голос і (за наявності ключа) побачити транскрипцію.
5. Переглянути матеріали від психолога.
6. Вийти з акаунта.

Усі дії відображаються на боці психолога в адмін-панелі (зокрема прослуховування голосу й транскрипція).
